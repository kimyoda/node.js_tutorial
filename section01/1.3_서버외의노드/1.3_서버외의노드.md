# 노드의 특성

## 이벤트 기반

- 이벤트가 발생할 때 미리 지정해 둔 작업을 수행하는 방식
  - 이벤트의 예: 클릭, 네트워크 요청, 타이머 등
  - 이벤트 리스너: 특정 이벤트가 발생했을 때 실행할 작업을 등록하는 함수
  - 콜백 함수: 이벤트가 발생했을 때 실행될 함수

- 이벤트 리스너에 콜백 함수를 미리 등록해 두면, 시스템에서 이벤트가 발생했을 때 등록된 콜백 함수가 호출된다.
- 여러 이벤트가 발생하면 **이벤트 루프**가 호출할 콜백의 순서를 관리한다.

```text
[콜백 함수]
      │ 미리 등록
      ▼
[이벤트 리스너] ◀── [이벤트 발생] ◀── [시스템]
      │
      │ 등록된 콜백 호출
      ▼
[콜백 함수 실행]
```

> **핵심 흐름:** 이벤트 리스너 등록 → 이벤트 대기 → 이벤트 발생 → 등록된 콜백 함수 호출

## 논블로킹 I/O

- **논블로킹**: 오래 걸리는 작업을 백그라운드로 보내 다음 코드를 먼저 실행하고, 작업이 완료되면 콜백 함수를 실행하는 방식
  - 논블로킹 방식에서는 일부 작업이 백그라운드에서 동시에 처리될 수 있다.
  - 백그라운드에서 처리할 수 있는 작업: 파일 시스템 접근, 네트워크 요청 등의 I/O 작업과 압축, 암호화 등
  - 일반 자바스크립트 코드는 메인 스레드에서 한 번에 하나씩 실행된다.
  - I/O 작업이 많을 때 Node.js의 활용성이 극대화된다.

```text
[메인 스레드] ── I/O 작업 요청 ──▶ [백그라운드]
      │                                  │
      │ 기다리지 않음                    │ 작업 완료
      ▼                                  ▼
[다음 코드 실행]                    [태스크 큐]
                                         │ 호출 스택이 비면
                                         ▼
                                  [콜백 함수 실행]
```

### 블로킹과 논블로킹 코드 비교

현재 프로젝트의 `blocking.js`는 오래 걸리는 함수를 직접 호출한다. 해당 함수가 끝나야 다음 코드가 실행된다.

```js
function longRunningTask() {
  // 오래 걸리는 작업
  console.log("작업 끝");
}

console.log("시작");
longRunningTask();
console.log("다음 작업");
```

```text
시작 → 작업 끝 → 다음 작업
```

`nonblocking.js`는 `setTimeout`에 콜백을 등록한다. 현재 코드가 끝난 뒤 콜백이 실행되므로 `다음 작업`이 먼저 출력된다.

```js
function longRunningTask() {
  // 오래 걸리는 작업
  console.log("작업 끝");
}

console.log("시작");
setTimeout(longRunningTask, 0);
console.log("다음 작업");
```

```text
시작 → 다음 작업 → 작업 끝
```

> `setTimeout(..., 0)`의 콜백도 현재 실행 중인 코드와 호출 스택의 작업이 끝난 후 실행된다.

## 프로세스, 스레드

- 프로세스와 스레드
  - 프로세스: 운영체제에서 할당하는 작업의 단위로, 기본적으로 프로세스끼리는 자원을 공유하지 않는다.
  - 스레드: 프로세스 내에서 실행되는 작업의 단위로, 부모 프로세스의 자원을 공유한다.

- Node.js 프로세스 내부에는 여러 스레드가 있지만, 기본적으로 자바스크립트를 실행하며 직접 다루는 메인 스레드는 하나이므로 싱글 스레드라고 표현한다.
- Node.js는 전통적으로 멀티 스레드 대신 여러 프로세스를 실행하는 멀티 프로세싱을 주로 활용했다.
- 강의에서 사용하는 Node.js 14에서는 `worker_threads` 모듈을 통해 멀티 스레드를 사용할 수 있다.

```text
[운영체제]
   │
   ├── [Node.js 프로세스 1]
   │      ├── 메인 스레드: 자바스크립트 실행
   │      └── 백그라운드 스레드들: I/O · 압축 · 암호화 등
   │
   └── [Node.js 프로세스 2]
          ├── 메인 스레드: 자바스크립트 실행
          └── 백그라운드 스레드들: I/O · 압축 · 암호화 등
```

> **구분:** 싱글 스레드라는 표현은 Node.js 프로세스에 스레드가 하나만 있다는 뜻이 아니라, 기본 자바스크립트 실행을 담당하는 메인 스레드가 하나라는 뜻이다.

## 싱글 스레드, 블로킹 모델

- 싱글 스레드는 주어진 일을 한 번에 하나씩 처리한다.
  - 블로킹이 발생하면 나머지 작업이 모두 대기해야 하므로 비효율이 발생한다.

- 주방에 비유(점원: 스레드, 주문: 요청, 서빙: 응답)

```text
[고객 1] ── 주문 ──▶ [점원 1명] ── 주문 전달 ──▶ [주방]
                         ▲                         │
                         └────── 요리 완료 ────────┘
                         │
                         └── 서빙 ──▶ [고객 1]

[고객 2] ── 대기 ────────────────────────────────▶
[고객 3] ── 대기 ────────────────────────────────▶
```

점원이 고객 1의 요리가 끝날 때까지 기다리므로 고객 2와 고객 3은 주문을 처리받지 못하고 대기한다.

## 멀티 스레드 모델과의 비교

- 싱글 스레드 모델은 에러를 처리하지 못하면 프로세스가 멈출 수 있다.
  - 프로그래밍 난이도가 비교적 쉽고 CPU와 메모리 자원을 적게 사용한다.

- 멀티 스레드 모델은 특정 스레드에 문제가 생겼을 때 다른 스레드를 사용하거나 새로운 스레드를 생성해 작업을 이어갈 수 있다.
  - 단, 새로운 스레드를 생성하거나 놀고 있는 스레드를 관리하는 데 비용이 발생한다.
  - 프로그래밍 난이도가 높다.
  - 스레드 수가 많아질수록 자원도 많이 사용한다.

- 점원: 스레드, 주문: 요청, 서빙: 응답

```text
[고객 1] ◀── 주문 · 서빙 ──▶ [점원 1] ──┐
[고객 2] ◀── 주문 · 서빙 ──▶ [점원 2] ──┼──▶ [주방]
[고객 3] ◀── 주문 · 서빙 ──▶ [점원 3] ──┘

각 점원은 자신이 맡은 고객의 요리가 끝날 때까지 대기한다.
```

각 고객에게 점원이 한 명씩 붙기 때문에 한 점원이 기다리는 동안에도 다른 점원이 다른 고객을 처리할 수 있다. 반면 고객 수에 맞춰 점원 수가 늘어나며, 손님이 줄면 놀고 있는 점원이 생길 수 있다.

## 싱글 스레드, 논블로킹 모델

- Node.js는 논블로킹 모델을 채택하여 일부 코드(I/O)를 백그라운드에서 실행할 수 있다.
  - 점원은 주문을 주방에 전달한 뒤 기다리지 않고 다음 고객의 주문을 받는다.
  - 요청을 먼저 받은 뒤 백그라운드 작업이 완료될 때 응답한다.
  - I/O 작업이 아닌 자바스크립트 연산은 메인 스레드에서 실행되므로, 오래 걸리면 싱글 스레드 블로킹 모델처럼 다른 작업을 막을 수 있다.

```text
주문 접수
[고객 1] ── 주문 1 ──▶ [점원 1명] ──▶ [주방]
[고객 2] ── 주문 2 ──▶ [점원 1명] ──▶ [주방]
[고객 3] ── 주문 3 ──▶ [점원 1명] ──▶ [주방]
                         └─ 요리를 기다리지 않고 다음 주문을 받음

완료 후 서빙
[주방] ── 요리 2 완료 ──▶ [점원] ──▶ [고객 2]
[주방] ── 요리 1 완료 ──▶ [점원] ──▶ [고객 1]
[주방] ── 요리 3 완료 ──▶ [점원] ──▶ [고객 3]
```

주문을 받은 순서와 요리가 완료되어 응답하는 순서는 다를 수 있다.

## 멀티 스레드 활용

- 강의 기준인 Node.js 14 버전에서는 `worker_threads` 모듈을 사용할 수 있다.
  - 하나의 프로세스 안에서 여러 스레드가 자바스크립트를 병렬로 실행할 수 있다.
  - CPU를 많이 사용하는 작업에 활용할 수 있다.
  - 기존에 멀티 프로세싱을 주로 사용하던 방식의 아쉬움을 보완한다.

```text
멀티 스레딩                         멀티 프로세싱

[프로세스 1개]                      [운영체제]
   ├── 스레드 1                        ├── 프로세스 1
   ├── 스레드 2                        ├── 프로세스 2
   └── 스레드 3                        └── 프로세스 3

프로세스의 자원을 함께 사용          각 프로세스의 자원이 서로 분리됨
```

| 구분       | 멀티 스레딩                                  | 멀티 프로세싱                               |
| ---------- | -------------------------------------------- | ------------------------------------------- |
| 실행 구조  | 하나의 프로세스 안에서 여러 개의 스레드 사용 | 여러 개의 프로세스 사용                     |
| 주된 활용  | CPU 작업이 많을 때 사용                      | I/O 요청이 많을 때 사용                     |
| 프로그래밍 | 공유 자원 관리가 필요해 어려움               | 비교적 쉬움                                 |
| 자원 공유  | 같은 프로세스의 자원을 공유                  | 프로세스 간 자원을 기본적으로 공유하지 않음 |
| 비용       | 스레드 생성과 관리 비용 발생                 | 프로세스 생성과 프로세스 간 통신 비용 발생  |

## 핵심 정리

- Node.js는 이벤트가 발생하면 등록해 둔 콜백 함수를 실행하는 이벤트 기반 방식으로 동작한다.
- I/O 작업을 백그라운드로 보내는 동안 메인 스레드는 다음 작업을 처리할 수 있다.
- 기본 자바스크립트 실행은 싱글 스레드이므로 CPU 연산이 오래 걸리면 다른 요청이 대기한다.
- I/O 요청이 많을 때는 이벤트 기반 논블로킹 모델을, CPU 작업이 많을 때는 `worker_threads`를 활용할 수 있다.
