# Node.js의 정의

## 공식 정의

Node.js 공식 홈페이지에서는 Node.js를 다음과 같이 설명한다.

> Node.js는 Chrome V8 JavaScript 엔진으로 빌드된 JavaScript 런타임이다.

Node.js 자체가 서버인 것은 아니다.  
Node.js는 JavaScript 코드를 브라우저 밖에서 실행할 수 있게 해주는 **JavaScript 런타임**이다.

다만 서버 개발에 필요한 `http`, `https`, `http2` 등의 모듈을 기본적으로 제공하기 때문에 JavaScript로 웹 서버를 만들고 실행할 수 있다.

---

## Node.js의 내부 구조

Node.js는 내부적으로 **V8 엔진**과 **libuv**를 사용한다.

### V8 엔진

- Google이 개발한 오픈 소스 JavaScript 엔진이다.
- JavaScript 코드를 빠르게 실행하도록 해준다.
- 2008년에 공개되었으며, Node.js 프로젝트는 2009년에 시작되었다.

### libuv

- Node.js의 이벤트 기반 구조를 지원하는 라이브러리다.
- 운영체제의 비동기 기능과 스레드 풀을 활용하여 I/O 작업을 처리한다.
- Node.js가 논블로킹 I/O 모델을 구현하는 핵심 요소다.

> Node.js의 JavaScript 코드는 기본적으로 하나의 메인 스레드에서 실행되지만, 모든 작업이 실제로 하나의 스레드에서만 처리되는 것은 아니다. 일부 파일 시스템, 암호화, DNS 작업 등은 libuv의 스레드 풀을 활용한다.

# 서버로서의 Node.js

## 기본 실행 모델

Node.js는 기본적으로 다음과 같은 실행 모델을 사용한다.

- 싱글 스레드
- 이벤트 기반
- 논블로킹 I/O

Node.js의 JavaScript 코드는 기본적으로 하나의 메인 스레드에서 실행된다.  
따라서 하나의 요청 처리가 끝날 때까지 기다리는 방식이 아니라, 시간이 오래 걸리는 I/O 작업을 시스템에 맡긴 뒤 다른 요청을 계속 처리한다.

이를 통해 하나의 메인 스레드로도 많은 I/O 요청을 효율적으로 다룰 수 있다.

---

## Node.js가 I/O 작업에 적합한 이유

서버에서는 다음과 같은 I/O 작업이 자주 발생한다.

- 네트워크 요청 처리
- 데이터베이스 조회
- 파일 읽기 및 쓰기
- 외부 API 호출
- 사용자 간 실시간 데이터 전송

Node.js는 이러한 작업을 논블로킹 방식으로 처리한다.

예를 들어 데이터베이스 조회 결과를 기다리는 동안 메인 스레드를 멈추지 않고 다른 요청을 처리할 수 있다. 따라서 동시에 많은 연결을 처리해야 하는 서비스에 적합하다.

---

## Node.js에 적합한 서비스

Node.js는 I/O 요청이 많고 데이터를 빠르게 주고받아야 하는 서비스에 적합하다.

대표적인 예시는 다음과 같다.

- 실시간 채팅 애플리케이션
- 알림 및 메시징 서비스
- 주식 및 암호화폐 실시간 차트
- JSON 데이터를 제공하는 API 서버
- 스트리밍 서비스
- 협업 도구
- 데이터베이스 요청이 많은 웹 서비스

특히 프런트엔드와 백엔드에서 모두 JavaScript를 사용할 수 있다는 점이 큰 장점이다.

---

## CPU 작업에 적합하지 않은 이유

Node.js의 메인 JavaScript 코드는 기본적으로 하나의 스레드에서 실행된다.

따라서 특정 작업이 CPU를 오랫동안 사용하면 이벤트 루프가 멈추고, 그동안 다른 요청을 처리하지 못할 수 있다.

다음과 같은 CPU 집약적 작업에는 주의해야 한다.

- 대규모 이미지 및 영상 처리
- 복잡한 수학 연산
- 머신러닝 모델 학습
- 대용량 데이터 변환
- 압축 및 암호화 작업
- 긴 반복문이나 동기식 연산

이러한 작업이 메인 스레드를 점유하면 서버 전체의 응답 속도가 느려질 수 있다.

Node.js에서도 `worker_threads`, 자식 프로세스, 클러스터링 등을 사용하여 CPU 작업을 분산할 수 있다. 하지만 기본적인 싱글 스레드 방식보다 구조와 관리가 복잡해진다.

CPU 연산이 서비스의 핵심이라면 다음과 같은 방법을 고려할 수 있다.

- CPU 작업을 별도의 서버나 프로세스로 분리한다.
- 작업 큐를 사용하여 백그라운드에서 처리한다.
- AWS Lambda나 Google Cloud Functions 같은 서버리스 서비스를 활용한다.
- CPU 연산에 적합한 다른 언어 또는 런타임을 함께 사용한다.

> Node.js 자체가 서버로 부적합한 것은 아니다. 다만 CPU 연산이 중심인 서버에는 상대적으로 적합하지 않다.

# 웹 서버로서의 특징

Node.js에는 웹 서버 기능이 내장되어 있다.

별도의 웹 서버 프로그램 없이도 `http` 모듈을 이용하여 간단한 서버를 만들 수 있다.

```js
const http = require("http");

const server = http.createServer((request, response) => {
  response.writeHead(200, {
    "Content-Type": "text/plain; charset=utf-8",
  });

  response.end("Hello, Node.js!");
});

server.listen(3000, () => {
  console.log("서버가 3000번 포트에서 실행 중입니다.");
});
```
