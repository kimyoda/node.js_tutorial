# 서버로서의 노드

## 서버와 클라이언트

- **서버(Server)**: 네트워크를 통해 클라이언트에 정보나 서비스를 제공하는 컴퓨터 또는 프로그램
- **클라이언트(Client)**: 서버에 요청을 보내고 응답을 받는 주체
  - 브라우저
  - 데스크톱 프로그램
  - 모바일 앱
  - 다른 서버
- 예시
  - 브라우저가 길벗 웹사이트 서버에 페이지를 요청하고 HTML, CSS, 이미지 등을 응답받는다.
  - 스마트폰이 앱스토어 서버에 앱 다운로드를 요청하고 설치 파일을 받는다.

```text
클라이언트 ── 요청(Request) ──▶ 서버
클라이언트 ◀─ 응답(Response) ── 서버
```

> **Node.js 자체가 서버인 것은 아니다.** Node.js는 브라우저 밖에서 자바스크립트를 실행할 수 있게 해주는 자바스크립트 런타임이다. 다만 `http`, `https` 등 서버를 만드는 데 필요한 모듈을 기본으로 제공한다.

## Node.js 서버의 동작 방식

- Node.js의 자바스크립트 코드는 기본적으로 하나의 메인 스레드에서 실행된다.
- 파일 읽기, 네트워크 통신, 데이터베이스 조회 같은 I/O 작업을 기다리는 동안 다른 요청을 처리할 수 있다.
- 작업이 완료되면 이벤트 루프가 등록된 콜백 함수의 실행 시점을 관리한다.
- 따라서 I/O 요청이 많은 서버에서 적은 자원으로 많은 연결을 효율적으로 처리할 수 있다.

> Node.js 프로세스 전체에 스레드가 하나만 있다는 뜻은 아니다. 일부 파일 시스템, 암호화, DNS 작업 등은 내부 스레드 풀을 사용하며, 필요하면 `worker_threads`나 여러 프로세스를 사용할 수도 있다.

## Node.js의 장단점

| 장점                                                                        | 단점                                                                    |
| --------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 요청마다 스레드를 만드는 방식보다 적은 자원으로 많은 연결을 처리할 수 있다. | CPU 연산이 메인 스레드를 오래 점유하면 다른 요청도 지연된다.            |
| 네트워크, 파일, 데이터베이스 등 I/O 작업이 많은 서버에 적합하다.            | CPU 작업이 많은 서버에는 상대적으로 부적합하다.                         |
| 공유 자원을 관리해야 하는 전통적인 멀티 스레드 방식보다 비교적 단순하다.    | 동기 함수나 긴 반복문이 이벤트 루프를 막지 않도록 관리해야 한다.        |
| `http` 모듈을 통해 웹 서버 기능을 기본으로 제공한다.                        | 여러 CPU 코어를 활용하려면 워커 스레드나 멀티 프로세스 구성이 필요하다. |
| 프런트엔드와 백엔드에서 모두 자바스크립트를 사용할 수 있다.                 | 서버 규모가 커지면 프로세스 관리, 로드 밸런싱, 모니터링 등이 필요하다.  |
| 자바스크립트 객체와 JSON 구조가 유사해 JSON 데이터를 다루기 쉽다.           | 비동기 흐름과 오류 처리에 대한 이해가 필요하다.                         |

> Node.js의 성능이 항상 어중간한 것은 아니다. 채팅, 스트리밍, REST API처럼 I/O 비중이 높은 서비스에서는 좋은 성능을 낼 수 있지만, 이미지·영상 처리나 대규모 계산처럼 CPU 사용량이 높은 작업에는 상대적으로 불리하다.

### CPU 작업을 처리하는 방법

- `worker_threads`를 사용해 별도 스레드에서 처리한다.
- 자식 프로세스나 별도의 서버로 작업을 분리한다.
- 작업 큐를 사용해 백그라운드에서 처리한다.
- AWS Lambda, Google Cloud Functions 같은 서버리스 서비스를 활용한다.

Node.js 활용 사례로 자주 소개되는 기업과 기관에는 PayPal, Netflix, NASA, Walmart, LinkedIn, Uber 등이 있다.

## 서버 외의 노드

- Node.js는 자바스크립트 런타임이기 때문에 용도가 서버에만 한정되지 않는다.
- 웹, 모바일, 데스크톱 애플리케이션의 **개발 환경과 도구**에도 사용된다.
  - 프런트엔드: React, Vue 등의 개발 서버, 패키지 설치, 빌드 과정
  - 모바일 앱: React Native, Expo 등의 개발 도구
  - 데스크톱 앱: Electron 기반 애플리케이션
  - 개발 도구: Visual Studio Code
  - 기타: CLI 프로그램, 테스트, 빌드 및 배포 자동화

> React와 Vue로 작성한 최종 코드는 주로 브라우저에서 실행되고, React Native 앱은 iOS 또는 Android에서 실행된다. Node.js는 이들의 패키지 관리, 개발 서버, 코드 변환, 번들링 같은 개발 과정에서 주로 사용된다.
